# 产品设计文档(PRD):企业岗位经验 Skill 生成平台

## 1. 背景与问题

企业引入 AI 员工(如经营分析 AI 员工)时,普遍遇到的落地障碍不是模型能力不够,而是**岗位经验无法规模化复用**:优秀员工的分析方法论(比如资深直播运营"先看流量漏斗、再做异常归因"的复盘套路)存在于个人头脑中,离职即流失;普通员工直接向 ChatGPT 类工具提问,得到的是通用回答,缺少本企业的业务框架、判断标准和输出规范,质量不稳定且不可审计。

本平台要解决的问题是:**让业务人员用一句自然语言,就能把岗位专家经验沉淀为结构化、可复用、可执行的 AI 员工 Skill**,无需写代码、无需懂 Prompt 工程。

## 2. 目标用户

**核心用户:业务团队负责人与资深业务专家**(如电商运营主管、销售总监)。他们最懂岗位方法论,但不会写代码。平台让他们把经验"存"进系统,放大自身影响力。

**次级用户:一线业务人员**(如新入职的直播运营)。他们是 Skill 的调用者,用现成 Skill 快速产出达到专家标准的分析,缩短成长周期。

**辅助用户:企业 IT/数据团队。** 负责 Skill 资产的管理、审核与数据接入,不需要为每个业务需求单独开发。

## 3. 解决企业什么问题

一是**经验资产化**:把隐性的个人经验变成显性的、企业拥有的数字资产,不随人员流动流失。二是**质量标准化**:同一 Skill 对所有人输出同一套分析框架、判断阈值和报告格式,消除"问法不同、答案参差"的问题。三是**降本提效**:一次沉淀、无限复用,新人也能立刻产出专家级复盘,减少重复性分析工作和培训成本。四是**可管理可审计**:相比员工各自使用外部聊天工具,Skill 的内容、版本、使用记录都在企业掌控内。

## 4. Skill 与 Prompt 的区别

Prompt 是一次性的自由文本指令,质量取决于提问者个人水平,不可管理、不可校验、难以复用。Skill 是**结构化的能力单元**:它包含 Prompt(Agent Prompt 是其组成部分之一),但还定义了使用场景、输入数据契约、分析流程和输出模板,并以 JSON 这种机器可校验的形式存在。可以这样类比:Prompt 是一句口头嘱咐,Skill 是一份标准作业程序(SOP)——前者依赖说话人的临场发挥,后者可以入库、审核、版本管理、批量分发,并保证每次执行的输入输出都符合约定。

## 5. Skill 的核心组成

本平台将 Skill 定义为 7 个部分(对应 skill_schema.py 中的 JSON Schema):

1. **Skill 名称**:简洁有辨识度,用于资产检索。
2. **Skill 描述**:能力与价值的一段话说明。
3. **使用场景**:3-5 个典型触发场景,帮助用户判断"什么时候用它"。
4. **输入数据定义**:字段名、类型、是否必填、说明——这是 Skill 与数据之间的契约,也是与纯 Prompt 最大的差异点之一。
5. **分析流程**:按顺序的分析步骤,承载岗位专家的方法论(如流量漏斗逐层拆解)。
6. **Agent Prompt**:执行时的系统提示词,包含角色设定、分析框架、判断标准(如"停留时长低于 30 秒即为异常")与数据纪律规则。这是 Skill 的灵魂。
7. **输出结果模板**:Markdown 结构化模板,保证报告格式统一、可横向比较。

其中最重要的是 **Agent Prompt 中的"判断标准"与"分析流程"**——它们承载了专家经验中最难获取的部分:不是"看什么数据",而是"数据到什么程度算有问题、该往哪个方向归因"。

## 6. 如何管理企业 Skill 资产

MVP 阶段 Skill 以 JSON 文件形式存储与分发(可下载、可导入)。规划中的资产管理体系包括四层:

**目录与检索**:按业务域(电商运营/销售/用户增长/零售门店)和岗位组织 Skill 库,支持按名称、场景搜索。**版本管理**:Skill 修改产生新版本,保留变更记录与回滚能力;判断标准的每次调整(如异常阈值从 30 秒改为 40 秒)可追溯。**权限与审核**:创建者提交,业务专家/管理员审核后发布;区分草稿、已发布、已下线状态;按部门控制可见与可用范围。**运营反馈**:记录每个 Skill 的调用量、用户评分和采纳率,低分 Skill 触发优化或下线,形成资产的优胜劣汰。

## 7. 如何验证 Skill 是否有效

分四道关卡,贯穿 Skill 生命周期:

**第一关,结构校验(机器,已实现)**:生成的 Skill 必须通过 JSON Schema 校验,必填字段齐全、结构合法,不合格自动重试修正。

**第二关,专家评审(人工)**:领域专家审查分析流程是否符合真实方法论、判断阈值是否合理、输入字段是否是业务中真实可得的数据。AI 生成提供的是高质量初稿,专家把关后才可发布——这一步不可省略,因为结构正确不等于业务正确。

**第三关,测试用例回归(机器+人工)**:为 Skill 准备带"已知病灶"的标准测试数据集(如一份停留时长 22 秒、转化率 0.7% 的直播数据),检验执行结果能否诊断出全部预埋问题、是否虚构未提供的数据。本项目开发中即用此方法发现并修复了模型虚构"目标值"的幻觉问题(治理前后报告见 docs/ 目录)。

**第四关,线上反馈闭环**:发布后跟踪用户评分与采纳率,结合抽样人工复核,持续迭代。

## 8. MVP 范围与验证结论

本 Demo 实现了最小可运行闭环:自然语言输入 → Skill 自动生成(含校验重试)→ 配置可视化展示(可下载 JSON)→ 粘贴业务数据调用执行 → 流式输出结构化分析报告。已在「抖音直播运营复盘」场景完整验证,生成的 Skill 具备真实运营方法论(流量漏斗、异常阈值、4P 框架),执行报告能准确诊断测试数据中预埋的全部问题点。

## 9. 后续规划(超出 MVP)

按优先级依次为:确定性计算层(指标计算由代码完成,LLM 只做解读,消除计算类错误)、Skill 资产库与版本管理、多轮对话式 Skill 精调(生成后与用户对话修改字段)、数据源直连(对接抖店罗盘/巨量百应等后台自动取数)、Skill 效果评估看板。
